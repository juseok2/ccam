# CCAM macOS 베타 0.2.1

SwiftUI로 만든 계정·대화 관리 앱입니다. Claude 작업은 기존 터미널에서 진행하고, 앱(창과 메뉴 막대)에서 계정별 사용량을 확인하고 대화를 이어갈 계정을 고릅니다.

## 0.2.1에서 바뀐 것 (0.2.0 대비)

## 본인 계정 두 개를 같은 설정으로 쓰기 (권장 구성)

1. **기존 대화 가져오기**로 `~/.claude` 를 `main` 으로 등록합니다.
2. `main` 을 쓰는 Claude를 **모두 종료**합니다(VS Code의 Claude 확장 창·터미널의 `claude` 포함). 실행 중이면 공유 설정 변경이 거부됩니다.
3. **계정 추가** → 이름 `sub` → 공유: **main 계정과 공유하는 새 그룹**, **대화 내역·프로젝트 메모리도 공유** 켬 → 열린 창에서 두 번째 계정으로 로그인.
   - `main` 의 설정·훅·CLAUDE.md·스킬·MCP·대화 내역이 ccam 공유 폴더로 옮겨지고 그 자리에 링크가 남습니다. 평소 `claude` 와 VS Code 확장도 링크를 따라 같은 파일을 봅니다. 바뀌는 파일은 ccam이 백업하고, 로그인 정보는 공유하지 않습니다.
   - 되돌리기: `~/.local/bin/ccam-team group leave <그룹> main` (각 계정이 사본을 가짐).
4. 사용량이 떨어지면 대화를 고르고 옮길 계정 `sub` → **옮기기…**. 복사 없이 그 대화를 쓰던 Claude만 종료하고 `sub` 로 이어갑니다.

같은 대화를 두 계정에서 동시에 열지 마세요. VS Code의 Claude 확장은 계속 `~/.claude`(= `main`)를 씁니다. `sub` 는 앱이 만든 명령을 VS Code 터미널에 붙여 넣어 씁니다.

## 설치 및 시작

Apple Silicon·Intel 겸용 로컬 베타입니다(Intel 실기기 실행은 미확인). macOS 13 이상이 대상이며 Claude Code가 설치되어 있어야 합니다. 앱에는 ccam 실행 파일이 포함되어 있습니다.

1. `CCAM.app`을 **응용 프로그램** 폴더로 옮긴 뒤 실행합니다. 압축을 푼 폴더에서 바로 열면 macOS가 임시 경로에서 실행하므로, 앱이 위쪽에 경고를 띄웁니다.
2. 평소 `claude`로 작업했다면 **기존 대화 가져오기**로 `~/.claude`를 계정으로 등록합니다. 폴더는 옮기거나 복사하지 않고 그 자리에서 등록하며, 홈 폴더의 `.claude.json`을 그 폴더에 연결합니다.
3. 다른 계정은 **계정 추가**로 이름을 정하고 열린 터미널·브라우저에서 로그인합니다. 로그인이 끝나면 앱이 스스로 알아채고 반영합니다(최대 5분 대기).
4. 이전에 쓰던 ccam 데이터 폴더가 있으면 **다른 데이터 폴더 연결…**로 `config`, `data`, `state`가 들어 있는 폴더를 고릅니다.
5. 계정 카드를 눌러 그 계정의 대화를 봅니다. 대화를 **두 번 누르면 바로 열리고**, 한 번 누르면 아래 막대에서 **이어가기 / 명령 복사 / 옮기기…**를 고를 수 있습니다. **새 대화**(⌘N)는 프로젝트 폴더를 고르면 바로 열립니다.
6. 왼쪽 **대화 여는 곳**에서 Terminal·iTerm·Ghostty 중 설치된 앱이나 **명령 복사만**을 고릅니다. 복사한 명령은 Cursor·VS Code의 터미널 탭에 붙여 넣습니다(Claude 입력창 말고).

명령은 `cd '<프로젝트>' && ~/.local/bin/ccam-team work --resume <ID>`처럼 짧게 만들어집니다. `~/.local/bin/ccam-team`은 앱이 실행될 때마다 다시 쓰는 작은 실행 파일이라, 앱을 옮겨도 복사해 둔 명령이 계속 동작합니다. 같은 이름의 다른 파일이 이미 있으면 덮어쓰지 않고 전체 경로 명령을 씁니다.

기본 데이터 폴더는 `~/.local/share/ccam-beta/runtime`입니다. 로그인 정보는 ccam 프로필·키체인 방식으로 관리하며 앱 파일이나 저장소에 넣지 않습니다. 앱이 실행하는 명령은 `CCAM_USER_HOME`으로 실제 홈 폴더를 알려 주므로, 가져온 `~/.claude` 계정도 평소 `claude`와 같은 키체인 로그인을 씁니다.

## 계정 관리

- 카드의 **…** 메뉴: 다시 로그인, 이름 변경, 로그아웃, 계정 삭제(폴더는 휴지통으로).
- **로그인** 버튼은 로그인이 필요하거나 만료된 계정에만 보입니다.
- 이름은 영문 소문자·숫자·`-`·`_`로 32자 이내이며, 입력하는 동안 바로 검사합니다.

## 사용량과 알림

- 5시간·주간 **남은 비율 = 100 - 사용률**입니다. 남은 토큰 수가 아닙니다.
- 앱을 켜 두면 5분마다, 그리고 앱으로 돌아올 때(1분 이상 지났으면) 자동으로 확인합니다. 창을 닫아도 메뉴 막대에 남아 선택한 계정의 5시간 남은 비율을 보여 줍니다.
- 어떤 계정이든 5시간 또는 주간 남은 비율이 10% 이하가 되면 초기화 주기마다 한 번 알림을 보내고, 가장 여유 있는 다른 계정을 함께 알려 줍니다.
- 두 값 중 작은 쪽이 가장 큰 계정을 **추천**으로 표시하고, 옮길 계정의 기본값으로 고릅니다.
- 확인하지 못한 값은 빈 막대(0%)가 아니라 점선으로 표시합니다. 초기화 시각은 "2시간 후 · 오후 4:30"처럼 보여 줍니다.

## 다른 계정으로 옮기기

1. 대화를 선택하고 아래 막대에서 옮길 계정을 고른 뒤 **옮기기…**를 누릅니다.
2. 확인 창에서 **이 대화를 쓰는 Claude**와 **다른 대화에서 실행 중인 Claude**를 나눠 보여 줍니다. 기본으로는 이 대화의 Claude만 종료하고, 다른 작업은 그대로 둡니다. 필요하면 **다른 대화의 Claude도 함께 종료**를 켭니다. 두 계정이 대화 내역을 공유하면 복사 없이 전환합니다.
3. **종료하고 옮기기**(실행 중인 Claude가 없으면 **옮기기**)를 누르면 종료 요청 → 백업 → 복사 → 검증 순서로 진행합니다.
4. 끝나면 대상 계정 화면으로 바뀌고, 완료 창에서 바로 열거나 명령을 복사합니다.

종료는 모든 대상이 Claude인지 먼저 확인하고(하나라도 아니면 아무것도 멈추지 않음), 신호 직전에 PID·시작 시각·프로필 소속을 다시 검사한 뒤 SIGTERM으로 요청합니다. 20초 안에 끝나지 않으면 강제로 끄지 않고 멈춥니다. 응답을 받는 중이었다면 그 응답은 끊깁니다. 어느 대화인지 기록이 없는 Claude(ccam 런처만 남긴 기록)는 안전하게 함께 종료하고, 백그라운드 데몬은 종료하지 않습니다(데몬의 작업 세션은 각자 대화 기록을 남김). 기록된 폴더가 없거나 사라졌으면 원래 프로젝트 폴더를 직접 고릅니다.

CLI로는 `ccam session running <계정> --session <대화 ID>`가 같은 범위 지정을 하고, `session transfer`는 언제나 그 대화를 쓰는 세션만 막습니다. 0.2.0의 `--cwd`(running)·`--running-cwd`(transfer)도 그대로 쓸 수 있으며, 주면 그 폴더의 세션도 함께 봅니다.

## 작업 중 표시와 오류

- 작업 중에도 창은 그대로 쓸 수 있고, 아래 막대에 진행 상황과 **취소** 버튼이 나옵니다. 복사 단계는 중간에 끊기지 않도록 취소할 수 없습니다.
- 오류는 무엇을 하면 되는지 한국어로 먼저 보여 주고, CLI 원문은 **자세한 내용**에 접어 둡니다(문제 제보 시 첨부).
- 복사할 수 없는 대화(마지막 줄을 쓰는 중이던 대화, 128MB 초과 등)는 주황색 이유와 함께 표시합니다.

## 소스 빌드

Go 1.26 이상과 **Xcode**가 있는 Mac에서(SwiftUI 매크로 `@State` 때문에 Command Line Tools만으로는 `swiftc`가 실패합니다. `xcode-select -p`가 CommandLineTools를 가리키면 앞에 `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` 를 붙입니다):

```sh
macos/build.sh "$PWD/../CCAM.app"
```

Apple Silicon·Intel 겸용(universal) 앱을 만듭니다.

기본은 로컬 테스트용 ad-hoc 서명입니다. 팀 배포용은 Developer ID로 서명하고 공증합니다:

```sh
xcrun notarytool store-credentials ccam-notary   # 한 번만
CCAM_SIGN_IDENTITY="Developer ID Application: …" CCAM_NOTARY_PROFILE=ccam-notary \
  macos/build.sh "$PWD/../CCAM.app"
```

서명에는 hardened runtime과 타임스탬프가 들어가며, 공증 후 앱에 티켓을 붙입니다(staple). MIT 라이선스는 앱 Resources에도 포함합니다.

## 검증 기록

0.2.1 (2026-10-29, macOS 27 Apple Silicon, Go 1.27.3, Xcode Swift 6.4):
- `go vet ./...`, `go test ./...` 25개 패키지 전부 통과(0.2.0의 `TestSourceHasNoHangul` 실패 해결).
- 새 시험: 대화별 종료(다른 대화·데몬·다른 대화의 ccam 중계는 종료 안 함, 확인 안 되는 프로세스가 있으면 아무것도 종료 안 함), 공유 대화 전환(복사·백업 없음, 깨진 마지막 줄도 전환), 같은 내역의 세 번째 계정이 쓰면 사전 점검에서 거부, 공유 폴더로 복사, 그 아래 링크 거부, 끊어진 공유 링크 오류, 복사 불가 대화 표시와 이유, 재개 폴더 규칙. 0.2.0의 프로젝트 범위 종료·`InScope`·가져오기 시험도 함께 통과.
- 격리 데이터 폴더에서 CLI로 가져오기 → 공유 그룹 → 두 번째 계정 참여(훅·CLAUDE.md·스킬·메모리 공유) → 공유 전환 → 비공유 복사·중복 거부, 계정 추가 순서(이름 오류 시 아무것도 안 옮김, 그룹 이름 충돌 시 shared2, 실패 시 빈 계정 회수)를 확인했고, 범용 빌드한 앱을 격리 폴더로 실행해 카드의 공유 표시와 미리보기를 캡처로 확인했습니다.
- 독립 검토 2회. 확인 못 한 것: 실제 로그인 계정 두 개로 앱 버튼부터 재개까지, Intel 실기기, VS Code 확장이 종료 요청을 받은 뒤의 동작, `/clear` 뒤 Claude 기록의 대화 ID 갱신 여부.

0.2.0:

- `go test ./internal/paths ./internal/profile ./internal/session ./internal/cli ./internal/transfer ./internal/config` 통과. 새 테스트: 프로젝트 범위 종료(다른 프로젝트 세션 보존), 가져오기 후보 JSON, `CCAM_USER_HOME`, `InScope`.
